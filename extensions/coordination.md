# Default coordination extension (`coord`)

Implements the coordination-v0 policy on public primitives; Python stdlib and `vqro_ext.py` only. This is a replaceable extension, not native agent/runtime policy. No terminal typing, process supervisor, automatic uncertain-effect replay or physical suspension.

## Dependencies and recovery

- C1 `operational.register/get/snapshot/apply`: one owner-bound domain `coord`, requested 4 MiB (C1 qualified 9,000/9,000 commits at 100 txn/s at this size; 8 MiB did not pass that load), no workspace fallback. Existing domains may grow but are never silently shrunk.
- C2 flat core callback fields `author, actor, principal, initiator, label, invocation`. Authority comes from the callback's effective principal, never arguments or a label. The live `invocation` proof propagates on writes/effects; it is never an `on_behalf_of` principal.
- C3 `resource.attach` item streams are optional read-only receipt observation: one bounded viewer, four opens per window, persisted cursor before continuation. Gaps reset this viewer, never replay input. Model text, coarse completion and other entities never become delivery receipts.
- C4 `resource.forget_cached` is cache-only, never native stop. Its actual identity-cache capacity remains marked unknown until exposed by the core.

Commands and subscriptions register before asynchronous operational bootstrap. Missing core support leaves commands visibly unavailable. A readable old snapshot remains stale/read-only even while registration or recovery mutation is blocked. Raw recovery remains usable. Owner/incarnation restart closes admission gates and turns unresolved claims into unknown; no native effect is repeated.

## Commands

All commands are `command.invoke` / `vqro run coord.<name>`. Every mutation needs a caller-chosen `op` prefixed by the current `coord.inbox.window` epoch plus `:`. `inbox.send` also needs a similarly prefixed `submission` scoped to that principal. Identical retries inspect original results, including well-formed validation/grant/quota refusals; changed intent conflicts. Retrying after a new grant needs a new op. Malformed/undeclared calls consume no slot. Refusal cache growth stays below the content ceiling, preserving both normal control-intent headroom and the entire recovery/archive share. Cached failures retain kind/fingerprint, not their full message; historical replies mark details incomplete. With no refusal slot, the actual refusal is returned live with `uncached: true` and a new `window` in error data, after durable epoch closure; that old operation ID can never become an admission after grants or space change. Saturation therefore still reports quota, not busy forever. A genuinely full bounded reply window can close busy before evaluation. Outside-window IDs never create new mutations. Inbox priority is `low|normal|high` (normal by default), editable only while pending. Per target/lane the highest eligible priority wins across senders, then equal-priority sender round-robin and FIFO. It never bypasses lanes, gates, quotas or unknown predecessors. There is no aging; sustained high traffic can starve low.

- `inbox.send`, `edit`, `withdraw`, `get`, `list`, `peek`, `op`, `resolve`.
- `scope {action: inspect, scope}` returns preconditions; `scope {op, action: pause|resume, scope, expect}` atomically selects gates. Scope names: `workspace`, `project:<id>`, `team:rN`, `agent:rN`. Results contain at most64 targets; follow `scope {action: result, receipt, page}` over the frozen selection. Capacity256, including200-agent scopes. A newly discovered unassigned endpoint invalidates an old workspace preview too.
- `control {op,target,action,args}`: declared native interrupt/respond/queue/session/configure/command/object/stop or administrative retire. No content FIFO. Native queue operations carry the runtime epoch; a recipe captures it from current facts, and an explicit queue control defaults it only when omitted (a caller-supplied stale epoch is preserved for native rejection). Stop closes admission first. `control {target,action:inspect}` returns `confirm_host:{resource,incarnation,endpoints}`; an explicit `host_kill` request must copy that snapshot unchanged. Every reported endpoint needs `stop` and has its inbox closed before invocation. The route/snapshot and grants are rechecked before dispatch. Confirmation is deliberately broad: unreported host work may also end; no atomic native endpoint-set fence is promised. Host termination never fabricates logical endpoint-ended evidence.
- `names`, `grants`, `membership.set` produce ordinary attributed configuration writes. Handles resolve once; public grant issuance pins aliases to exact principals/targets. Membership is an acyclic project/reporting forest; no parentage grants rights. Every conforming mutation validates the whole forest and includes a CAS of `doc/agents/membership-revision` in the same ordinary workspace transaction; disjoint concurrent moves cannot jointly introduce a cycle. Names never add a principal to an agent/team; optional principal aliases are resolved only at authorized grant issuance and cannot contradict known native identity. Raw/imported invalid membership is preserved and reported in `coord.status.configuration` with the cycle/error. Workspace, project-field and exact-agent selection, direct/project/wildcard grants, sends and pulls do not need a valid reporting forest. Only team-dependent grants/scopes fail closed as `membership_invalid`; a direct valid grant still works even if a separate team grant is unusable. No edges are quietly repaired. Undo changes membership, not earlier scope authorization.
- `handover` freezes an inspected pending-delivery list (maximum58) and recorded ordinary stages. `action:stage, plan, stage` advances each checked CAS stage; `action:complete, plan` releases only after every stage succeeds and records the successor's current session as the target pin; explicit sender guards remain unchanged. `action:abort, plan` restores only pending records to their original target/held state and does not open any gate. Both completion and abort skip listed records that are no longer pending (for example withdrawn), preserve their final state, and do not strand the remaining records. Abort explicitly does not revert accepted or independently settling configuration stages. Claimed/unknown work stays with the predecessor; no destination gate opens automatically.
- `inbox.archive {op,agents,destination,deliveries?}` freezes a bounded inspected set (maximum48 records). Then explicit `action:export, archive` writes and syncs a new content-hashed file without overwriting any existing different bytes; `action:free, archive` frees only unchanged source versions after readback. Late changed evidence stays in place. `action:inspect` shows the plan. Source evidence is never silently evicted on quota; missing/tampered archived files are unknown, not no-effect. An active claim cannot be archived before it settles or becomes unknown.

A gate is inbox admission state only. Native turns, queues and retries may continue while “inbox paused.” Pause/resume have fresh explicit opposite controls, outside global undo; they cannot undo external effects. Unknown predecessor ordering blocks only its sender/target/lane, not every queue. Native stale rejection latches review-required even for follow-current-session input; resume, new session facts and retries cannot clear it. An explicit versioned edit can.

## Tier-1 pull

The endpoint declares `pull {points,insert,evidence}` in its facts (or a designated terminal marker's `pull`). Launcher/configuration grants its actual plugin principal `receive` for the exact endpoint. A plain terminal without a plugin remains manually usable and holds its mail.

1. Get a current operation epoch.
2. At consumer load, call `coord.inbox.reconcile {op,agent,consumer,records:[{delivery,entry?}]}`. A new consumer fences the old one on the first confirmed page. Reconcile processes at most56 records/112 KiB of changed records per call and returns `state:reconciling`, `remaining` and `next` while work remains. Repeat with fresh operation IDs and the same consumer/proofs until `reconciled`; no take or autonomous input is admitted mid-transition. Already-unknown records are not recounted without new positive entry evidence. An actual durable entry gives inserted evidence only if that integration declares `evidence:entry`; otherwise old claims become unknown. Entry evidence over1 KiB is explicitly retained as a size/hash/incomplete descriptor, never silently truncated.
3. At a real declared `turn|settle|idle|tool` point, call `coord.inbox.take {op,agent,consumer,at,limit,accept:[block types],max_bytes?}` (limit1–16). `accept` has1–16 distinct bounded names; omission is conservative text-only. `max_bytes` is1–262144, default32 KiB, measured over compact UTF-8 JSON content. Unsupported/oversized records stay unclaimed with `unsupported_content`/`too_large_for_consumer` for that consumer; eligible later input may progress. Reason updates and claims share a bounded C1 write budget, so a batch can contain fewer than the requested limit. `points` is a map of per-point `precision:exact|approximate`; unknown precision fails closed. List-form or malformed declarations are rejected visibly as `invalid: declaration_invalid`, not silently treated as a missing integration. Approximate idle can serve boundary/settle, never a start that assumes the runtime stayed idle. Missing/unknown points reject. Paused gates return no content.
4. Insert each returned record, framed with its `origin`. Context insertion requires the sender to accept `render:["context"]`; it is not silently a user message.
5. `coord.inbox.report {op,delivery,claim,consumer?,stage}` advances the real pull claim only. `inserted` needs declared entry evidence; `supplied` is context/no-entry; `released` is only an uninserted pull claim. Native dispatcher claims cannot be released or reported through this API.

Lost take replies are inspected with `inbox.op`: repeats return claim history, **never content to insert again**. Unresolved claim history remains discoverable through the retained `attempt.take` identity after the operation window/cache rolls; an expired mutation is never recreated. The protected record preserves the content and attempt for explicit reconciliation. Wake publication is count-only, tagged with control epoch/revision; a hint is never authority to start work or bypass a new gated take.

## Bounds and evidence

Default domain4 MiB; sender-target quota8 open/128 KiB; sender and target quota64 open/512 KiB each. Content32 KiB. At least10% domain recovery/control reserve, plus explicit pending outcome and tombstone reservations. New potentially-uncertain external intents are charged to the normal ledger budget while retaining control-lane IO priority; they cannot consume recovery space. Ordinary content leaves64 KiB/16 normal-budget records for bounded control intents, so content floods cannot consume that share. Inside the existing10% recovery reserve, the last64 KiB/16 records are archive-only; other controls retain the remainder. Each of at most four active archive plans pre-reserves16 KiB/four future records for export/free/locator metadata, reduced to8 KiB/two after export. Outcomes persist as compact per-step evidence≤1 KiB (kind/stage/operation/size/hash and `incomplete:true`); recipes reserve up to3 steps. Absent optional native-send fields are omitted from requests, not encoded as null objects. Full native results appear unchanged only in the live caller's reply; a historical lookup is explicitly compact. Dispatched `origin.sender` preserves the original recorded `from` with `provenance:inbox-record`; transport principal/actor come from the core's authenticated connection attribution, never a hardcoded or borrowed sender identity. Pull replies retain that original sender separately from their actual receiver-call attribution. Reported RPC errors retain the original raw error in the live reply. Only explicit `data.outcome` supplies error certainty; kinds never substitute for it. Local preconditions and transport failures without an original reply have `native:null`, not a fabricated native result; step evidence distinguishes coordination from native replies. Pages≤64 items/256 KiB, scopes≤256, pull batches≤16. `coord.status` publishes the effective limits, not an unqualified throughput claim.

Three-KiB tombstone summaries are reserved from first coordination state and paged so200-target scope selection remains one atomic write. Known-ended identity is sticky. A beyond-contract oversized identity becomes explicitly incomplete/hash-marked, is visible in attention status, and holds only that target as `identity_unavailable`; whole-scope gate changes still select every target atomically. Native input has at most eight independent target workers and one in-flight attempt per endpoint. Final history retains256 compact records plus a bounded1024-entry settled index; current-window submissions stay indexed even after history compaction. Unresolved attempts, incomplete pull claims and frozen archives are not silently pruned. Operational evidence and gates remain outside global undo.
