# Work decisions V1 (no-model)

Public extension-side decision registry for the [frozen V1 ABI](../../docs/next/api/v1-decision-contract.md). `index.mjs` exports `createDecisionRegistry({broker})`. The registry evaluates six asynchronous points using the frozen deterministic reference default, or an exact registered provider selected by ID with Work-authorized capability/generation. No model requests, client socket, task storage, terminal input or action commit live here.

```js
import { createDecisionRegistry } from './index.mjs';
const decisions = createDecisionRegistry({broker: {
  admit: async input => ({request: workBuiltRequest(input), actor_id: hostActorId, store_id: storeId, store_generation: storeGeneration}),
  current: async admission => workAndHostCurrentFacts(admission),
  authorizeProvider: async (admission, provider) => currentExactCapabilityGrant(admission, provider),
}});
const {request, result, plan, provenance} = await decisions.resolve(input, {providerId, signal});
```

`admit` is a **trusted Work/host adapter**, not a client-input mapping: Work builds actor class, assigned roots/graph, exact source/run and human route authorization from its own canonical snapshot and host lease. `current` re-reads `{store_id, store_generation, actor_id, scope_id, actor_current, execution_current, source_current, input_revision, input_digest, policy_revision, provider_generation}`. `source_current` means exact canonical source entry/version, claim/run and current human-route authorization/revision are still verified; `true` is appropriate for points without a source. `authorizeProvider` checks the exact artifact capability grant and generation at evaluation and before a selected result is returned. The registry passes optional `{signal, remainingBudgetMs}` to `current(admission, options)` and `authorizeProvider(admission, provider, options)`; every post-admission broker await is bounded by the original host-monotonic deadline/cancellation, with at most 32 unsettled broker callbacks retained. Work should honor abort promptly rather than leave a bounded slot occupied. Registration alone grants no authority. `registry.interfaces()` returns bounded, immutable point/contract descriptors for Work to filter by caller grant and expose through separately advertised `extension.interfaces.list.v1`; it is not an invocation lease. `resolve` returns immutable **advisory** objects plus `async revalidate()` for Work to call immediately before CAS, never a durable receipt: `plan.kind` is `no_effect | proposal_only | record_suggestion | request_confirmation | commit_action`; `commit_action` is possible only for hard-policy-allowed action confirmation in `auto_apply` mode. For a manual/confirm interaction use the ABI's `suggest` mode, then an explicit current-revision human action.

The Work provider must call `revalidate()` before its commit and repeat actor/source/graph/policy/input/generation, host monotonic invocation deadline/cancellation and exact target checks in its own public action path and same journal CAS; the return from `revalidate()` alone is not authority. It atomically appends `provenance` with effect and outbox, and resolve uncertain commits by canonical receipt lookup. A `turn.output_route` plan merely selects a target: it never posts a reply. A human route exists only through canonical `work.output.route.v1` consent, never an adapter flag. A Work-built human-route context without an exact matching source/run/recipient is rejected as `no_effect` even if the inert frozen reference would select that target; Work must never construct such inconsistent context. On stale/cancelled/expired state the registry returns `no_effect`; Work still owns recording nonconsequential resolution audit where safe. A selected provider timing out never extends its monotonic deadline. Provider invocations are bounded (32 total, four per provider); an uncooperative timed-out callback retains its slot until it actually settles. Real host/process termination, execution isolation and durable broker/Work qualification are separate 2B/3 work.

`just work-contract-test` runs inert registry/fake-broker tests alongside frozen reference tests. The fake broker models CAS/audit refusal only: it does not establish production actor authentication, durable journal/outbox, restart recovery, final Pi output or full JSON Schema validation.
