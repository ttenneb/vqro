# V1 work contract candidate (Slice 2A)

**Status: proposed/freeze candidate, not an available API.** Slice 2B/3 must not start until PM accepts this contract. Existing `agent.prompt`, staged package leases and `extension.state.*` do not implement it. No frozen generation-1 codec or advertised old method is changed by these documents. New neutral methods must be separately advertised; absence disables only work actions/composer, never terminal use or another server.

This contract belongs to an extension. The host stores opaque versioned records, authenticates caller/subject leases and enforces generic bounds/fences. It does not know a task, thread, subtree, report or acceptance. Names below describe the **work provider's** registered actions, not host `Method` variants. Non-reserved namespaces and explicit grants use the same public admission path.

## Identity and trust

Three identities are different:

1. **Producer principal:** host-authenticated client or installed service identity, namespace grants and current generation. Clients cannot supply or override it in an action payload.
2. **Actor:** host-issued stable opaque `actor_id` associated with an explicitly authorized binding; work provider records semantic class human/agent/service. Names/role labels are presentation, not keys or permission proof.
3. **Execution:** host-issued `execution_id` for a foreground execution epoch (terminal identity + process birth/lifecycle and session binding observations). Pane/workspace/tab are optional placement joins, not address identity. A new process/session gets a new execution. Reported session identity is labeled reported; no role or final-provider verification is implied.

Initial local-session operator consent creates the human client binding and authorizes exact execution-scoped adapter registration tickets through **public neutral registration**. Tickets are single-use, short-lived, bound to subject and registrar; actor credentials are secret and never placed in prompts, task bodies, CLI arguments, snapshots or logs. This is user-authorized registration on a trusted same-user machine, **not** an OS isolation or malicious-same-UID defense. An adapter cannot simply claim `kind=human` or another actor ID. Installed services receive their own principal; user attribution only comes from a host-issued invocation lease. Autonomous provider records attribute the provider, not a human.

Operator/adapter bootstrap uses public peer-credential/PID-birth ancestry checks and a one-time consent challenge, ticket take/private callback transfer and same-execution lost-response recovery; see the neutral contract. A managed-execution caller cannot request operator authority by a boolean/kind claim. Credentials have a10-minute live lease, renewable only under current binding/authority; tickets/challenges60seconds. Work actor class is derived from host operator/execution/service subject scope, not client input.

Actor credential renewal retains actor ID only for the same validated execution; replacement/session switch retires the binding. Server restart invalidates live leases until revalidation against exact execution facts; unknown facts hold delivery, never infer continuity from a title/path. Rebinding a different execution/task is explicit human action. Old actor receipts remain readable by the authorized human recovery route and retain original actor provenance. No automatic readdress or wake.

## Work state and typed entries

The extension owns stable opaque task IDs, optional acyclic task parents, monotonic decimal-string task revisions, creator/participant/assignment actors, and work state `active | blocked | reported | accepted | rejected | archived`. `reported` is waiting for review, not accepted/done. The extension validates every transition; runtime lifecycle never changes task state by itself.

Entries have immutable `entry_id`, `thread_id`, `parent_entry_id` (null for root), `task_id` (null for a free-standing thread), `kind`, author actor + immutable producer attribution, addressed recipient or null, body/evidence, source action ID, and commit cursor/time. Types include message, assign, question, reply, report, accept, reject, block and resume. Thread ancestry and task ancestry are separate. Root/parent must exist and belong to the same thread; no cycles, cross-thread parent substitution or history rewriting. Attaching a free thread later records a new link event; original provenance stays intact.

Assignments and directed entries use exact registered actors, not pane labels. Available and registered-offline actors may receive exact durable queues without wake. Registered actors with unknown execution evidence may receive held queues, never claim until revalidated. Retired actors cannot receive a new enqueue; unregistered IDs are not actors. Old unread queues/receipts are retained for operator recovery, never inherited by replacement. Recipients gain only the explicitly recorded participation needed for that entry/task; no cross-subtree read permission inferred from a role. For work envelopes, mailbox source entry/version/body digest is verified against the canonical work record before pickup; raw transport edits cannot silently change a typed work entry. Work V1 does not expose a semantic edit action; future edits must append explicit immutable versions and preserve thread history. A report carries evidence and the task revision it proposes; accept/reject references that report and current task revision, preserving the report and earlier decisions. Accepted/rejected work is not reopened by a duplicate reply. Block entries mark the actor's own active work blocked; final assistant prose is never implicit report or acceptance.

## Common action envelope

A client invokes the neutral action broker with namespace/service/action contract and registered action name, stable client operation ID, expected provider generation, and JSON input. Actor credential is on the authenticated transport, not in input. The host injects immutable caller/actor/execution/lease context. Work payloads use strict versioned schemas: unknown load-bearing fields/actions/versions reject, not ignore-success. Read-only actions are declared as such; mutation/suggestion are distinct. All counters/revisions are decimal strings (avoid JS precision loss); IDs are opaque bounded ASCII, not paths.

Mutating input has expected store ID/generation and expected affected task/thread revisions. The provider resnapshots and checks those plus current actor scope immediately before a journal CAS. Concurrent unrelated changes may require internal retry/resnapshot; a semantic conflict returns conflict and preserves drafts. Core sees only generic stream CAS, never task ancestry or actor subtree policy. Operation dedupe key is namespace + original actor ID + operation ID; stable semantic digest excludes ephemeral connection/deadline/lease data. A different payload under a reused key conflicts. A committed duplicate returns the original receipt, even after provider restart.

### Registered V1 action vocabulary

| Work action | Required input / semantic result |
| --- | --- |
| `work.task.create.v1` | parent task or null, title, initial body, expected parent revision; commits task + root entry |
| `work.task.assign.v1` | task ID/revision, exact actor recipient, optional note; commits assignment + offer/outbox |
| `work.entry.post.v1` | task/thread/parent refs, message/question/block kind, exact recipient if directed, body; commits entry/outbox |
| `work.entry.reply.v1` | exact source entry/thread/task refs + revisions, recipient, body, run ID (null for human); agent run/claim proof mandatory; commits typed reply |
| `work.report.propose.v1` | task/revision, thread/source refs, bounded evidence/body; commits report, never acceptance |
| `work.report.accept.v1`, `work.report.reject.v1` | exact report entry + current task revision, reason; explicit recorded acceptance/rejection |
| `work.resume.v1` | current task/execution, observed idle revision, reason; human-confirmed typed resume, no pane input |
| `work.output.route.v1` | human-only source/thread/execution/epoch, optional exact run, expected route revision, route/recipient/reason; durable authorize/change/cancel output route, no model start |
| `work.proposal.confirm.v1` | proposal ID/input revision, explicit chosen action, reason; revalidate and commit once |
| `work.decision.override.v1` | decision/proposal ID, point, current revision, replacement choice + reason; new audit record |
| `work.read.v1`, `work.receipt.get.v1` | authorized bounded task/thread/query cursor or original operation key; read-only |

Human composer and thin Pi tool adapter use these exact registered actions. Composer form definition is extension-owned, transported by public generic service interface; client owns modal state, focus/paste and drafts. No CLI-only private shortcut. Input is never typed into a pane. Read-only form/context requests cannot grant consequential authority. Clients call separately advertised `extension.query.invoke.v1` with `work.read.v1` or `work.receipt.get.v1`, never mutation admission/direct owner journal access. Work read returns `vqro.work.read.result.v1` with store/generation/snapshot, bounded task/thread/entry/route-authorization arrays and generation-bound cursor; total<=128 records and64KiB. Receipt query returns canonical receipt or explicit key/domain-only missing branch. Provider receives immutable caller/read-only lease and filters scope; stale cursor/provider gives local error/resnapshot.

### Public human output-route producer

Composer and public CLI/Pi tools expose `work.output.route.v1` with the strict `outputRoute` schema. Only a current operator-origin explicit invocation can authorize/change/cancel; an agent may suggest but cannot create the authorization. Work checks source/thread/task permissions, exact execution epoch and current route revision, then CAS-appends the authorization with immutable human actor/producer attribution and reason. This occurs **before** evaluation/settlement and needs no existing decision ID. `work.read.v1` returns current route revision/authorization with the authorized source context; the shared extension form supplies the same action, never pane input.

Before run exists, `run_id=null` requires authoritative no-run evidence; grant targets that exact source/version + execution/epoch. V1 host allows only one logical run per exact delivery/version, so the grant resolves to its sole verified host-issued run; start uncertainty is not permission for a second run. For an existing run, its exact ID is mandatory. Work combines canonical grant + narrow host run receipt to construct `human_route`, not adapter flags, and records consumption/binding with reply/decision in the same journal CAS. Default-thread choice/cancel increments route revision; replacement/cancel/stale source invalidates the grant. A route change after reply already committed rejects rather than rerouting history. No route action wakes/starts an agent.

### Approved authority policy

- Agents may create, assign and message/report/block within their **currently assigned task subtree**. Scope is computed from current work state and actor binding, never caller-provided ancestry. Creating a root/unassigned task or free-standing message is suggest/confirm for agents. Default `thread_reply` is target selection, not permission to post: an agent reply in a free thread without assigned-task scope becomes a durable suggestion until explicit human confirmation. No hidden synthetic task or silent scope grant.
- Accept/reject and cross-subtree reassignment default to suggest/confirm. A within-subtree reassignment is still revision/recipient checked; actor replacement never silently inherits scope.
- Human override/confirmation is explicit, current-revision checked and recorded. An agent cannot confirm its own proposal as human.
- Explicit-recipient, queue-only routing; no automatic wake/owner launch. Missing recipient yields unresolved proposal, not a guess. A block/report is a typed message action, not permission to accept work.
- No action while identity, scope, store generation or provider binding is unknown/stale. Unknown role proof does not create privilege. Approval policy is already human-approved; this document does not ask again.

## Receipts, outbox and recovery

Receipts also distinguish `proposal_only` from `applied` or `no_effect`; committing an audit/suggestion does not mean the requested task action happened. Distinct stages: invocation durably admitted; semantic journal committed; addressed envelope durably enqueued; claimed; Pi run started; reply/report committed; human accepted/rejected. UI must not call admitted/claimed/report 'done'. A provider callback is not durable commitment: an applied result must reference host-verified journal evidence bound to actor/operation/digest, or remain provider-claimed/unknown.

The work provider atomically appends semantic state delta + operation receipt + decision/audit provenance + addressed outbox intent to its own neutral journal stream. Audit persistence failure/quota blocks consequential apply, including fallback; never execute with fictional later audit. Host-stamped deferred-delivery manifest binds original actor/op and payload pointer/digest. Post-crash owner recovery uses a separate current service lease and that exact committed intent, not a dead user lease; original semantic author and recovery transport principal remain separate. It then sends the outbox through the neutral durable mailbox with a stable delivery ID. These stores are **not** one transaction. Failed/uncertain delivery retains pending intent; lookup by delivery ID resolves it before retry. Enqueue dedupe includes original actor + immutable payload digest. A later journal acknowledgement links the transport receipt. A crash at any boundary is visible/reconcilable, never silent replay.

Semantic validators require unique, non-conflicting precondition refs for all affected tasks/threads; empty or omitted affected revisions are not an authorization escape. Confirmation cannot recursively confirm/override another confirmation; chosen action must match the recorded proposal, with original proposer and actual human committer recorded separately. Entry author/producer fields must match immutable host append attribution, never caller claims.

Lookup replies have explicit non-record branches: verified `absent` contains only lookup key + expected receipt-store ID/generation + `authoritative_absent` assurance; unknown/retired/repair contain the same key/domain with `not_authoritative`. Missing data never invents digest/provider/sender/recipient/version. Receipt domains are discovered and persisted before submission; mismatch/retired generation cannot authorize retry. A Work receipt query propagates these neutral lookup branches unchanged until a canonical work receipt exists.

Unknown action result → lookup original operation key. Lookup distinguishes committed, rejected, pending/unknown, absent within current epoch, retired epoch and unavailable/repair required. Only authoritative absent + valid unchanged preconditions may be submitted; unavailable/retired/unknown never means safe resend. Human recovery can inspect an old actor's receipt without reattributing the action. Caller disappearance after persistence begins does not abort a potentially committed write. Persistence uncertainty fences writes/claims until recovery; no optimistic acknowledgement.

Generic unstamped waiting message edits are CAS updates before claim only, preserving original/version history. Stamped work-intent envelopes cannot be edited at transport layer; Work V1 has no semantic edit action. An unresolved deferred intent holds a mechanical transport pin until durable enqueue or explicit verified abandonment, even if semantic archive requests unpin. Claim atomically freezes the delivered version and exact recipient execution; replacement/expired claim lease cannot silently reassign to another execution. Reply references the actually claimed version, not latest editor text. Cancellation is a recorded action/outbox transition, not retroactive deletion of read content. Delivery/body reads require actor or explicit operator scope. The work owner has narrowly granted claim/run receipt access only for its stamped intents; it verifies the exact claimed version and host-issued run ID without impersonating the recipient.

## Decision and Pi contracts

See [decision ABI](v1-decision-contract.md) and [neutral mechanics/capabilities/failure matrix](v1-neutral-mechanics.md). V1 ships deterministic defaults only. Suggestions do not write consequential work; auto-apply still uses this public action path and current CAS. Provider/rationale/override/fallback provenance is recorded.

At pickup the Pi adapter obtains a host-issued run bound to exact claim/version/actor/execution, persists source entry/thread/task/run correlation in its public opaque actor checkpoint and Pi session data **before** native submission, then acknowledges adapter-reported start. Missing start ACK is uncertain and reconciled, never automatically rerun. `agent_settled` is notification-only: at settlement the adapter must resolve exactly one final persisted response and successful outcome for that matched source/run, accounting for retries/continuations/context edits. Neither the last `turn_end`, `agent_end`, nor settlement notification alone is final-output proof. The qualified response invokes `work.entry.reply.v1`; explicit routed tools dedupe/supersede observer routing. Abort/error/multiple ambiguous sources leave pending/unrouted state, never last-thread guessing. Human output is a separate explicit route requiring a canonical human-authored authorization bound to this run/current scope and immutable operator attribution; an adapter `available`/recipient flag cannot supply it. Report is explicit tool/action only; acceptance is never inferred from prose.

Stalled advisory is extension-derived: assigned active work, exact execution settled/idle, no blocked/reported/waiting-human state or queued continuation, no progress. It is not a task mutation. Missing/stale/replaced facts mean unknown. Human can explicitly resume via typed action/adapter delivery; no auto-resume/wake and no pane input.
