# V1 neutral mechanics candidate

**Proposed Slice 2A contract, unavailable until 2B implementation/qualification.** Every method below is a new separately advertised JSON method. Exact field-level candidate requests/results/errors are generated in `contracts/work-v1/api.schema.json` from `api-shapes.mjs`; host context is transport-injected, not request params. Catalog limits and authority/semantic checks below are part of the contract. No new field/variant is added to a frozen generation-1 codec. Missing method/capability is feature-local unsupported, not compatibility disconnect or fallback to pane typing. Generic service requests carry opaque extension contracts; core never parses work action names or task ancestry.

All namespaces are non-reserved installed owner namespaces; no bundled first-party capability exception. Ordinary trusted executable services must receive these grants through public production admission, not staged pinned-package leases or private sockets. Read does not imply write/send/claim. Operator scope is explicit, not guessed from a process title. Ticket issuance/binding does not wake an agent or assign a task.

Lookup endpoints distinguish existing receipts from closed `absent`/`unknown`/`retired`/`repair_required` branches. Non-record branches carry only the exact requested lookup key/domain and assurance: `authoritative_absent` only after integrity/current-domain verification, otherwise `not_authoritative`. No invented provider/digest/sender/version. `extension.interfaces.list.v1` publishes action/mailbox receipt domains; clients persist them before invoke/enqueue and pass expected domains to lookup. Domain reset/retirement fences old lookups, never absent-and-replay. Mailbox envelope/claim/run receipts carry that mailbox domain; claim/renew/ACK/run-bind/start-ACK/run-lookup require expected domain. Old-domain run lookup returns retired/not_authoritative (no invented run fields), and mutation rejects stale generation. IDs remain opaque; no reliance on guessing ID reuse. Namespace reset must durably retire related receipt domains under a recovery barrier before accepting new mutations; interrupted retirement is repair-required, not a fictional cross-store transaction.

Public queries are separately advertised `interface_kind=query` handlers, not mutation tunneling. `extension.query.invoke.v1` authenticates actor and issues an immutable caller context with request ID as correlation/operation field, input digest, deadline and **read-only** namespace/receipt capabilities. Host rejects journal writes/mailbox sends through that lease; Work filters records/route authorization to actual caller's granted scope. Result generation is rechecked on completion; unsupported/stale/timeout is query-local, not disconnect. Query result does not certify a later mutation; clients resubmit current action preconditions. Owner-only `namespace.journal.read` is internal to Work service, never granted to composer/agent clients.

### Immutable caller context

The broker passes host-issued `server_id`, `boot_id`, principal ID/type (client/service), actor ID, optional execution ID/epoch, namespace/service/provider generation, operation ID/input digest, invocation ID/deadline and allowed capabilities. Clients cannot include a replacement caller context. Services append using this lease; autonomous maintenance is attributed to the service, not the originating user. Credentials/tickets are transport secrets and excluded from records/logs/UI. Evidence source/trust is explicit; same-user executable trust is not a sandbox or role proof.

### Operator and adapter bootstrap (Linux V1; no private TUI privilege)

The public API authenticates local owner socket credentials and captures peer PID/birth. A platform trait resolves managed foreground execution ancestry (not role/title claims). A peer inside any managed execution (PTY or executable service, including descendants) cannot obtain an operator principal, even when it sends `consent=true`; an unprovable peer is rejected. This denies registered agent/service origins, not arbitrary external same-UID code, and does not prove a human gesture. Persisted consent is distinct from the temporary controller connection so a completed CLI consent can outlive that CLI; a new execution still requires new consent. Controller registration/one-time challenge/explicit UI or CLI confirmation occurs outside managed execution ancestry through these same public methods. Operator confirmation is an authorized controller assertion, not cryptographic proof of a human gesture; malicious same-UID escape/credential theft remains outside trusted V1. No special TUI socket/client namespace gets authority.

Operator authorizes a current execution ticket without sending a secret through its pane. The adapter's internal public CLI/API call is verified against socket peer PID/birth/ancestor and host execution/session epoch before it can take/bind the ticket. The adapter consumes the secret via private callback pipe/memory, not a model-visible tool result. Reparented/wrong execution/changed session fails. Credentials remain in adapter memory (or explicitly approved private credential storage during real installation); never prompts/argv/session text. Bind-response loss has a same-execution recover/rotate route, not blind ticket replay. Linux platform proof is required for V1; unsupported backend disables actor actions, not compatible terminal connections.

Execution IDs are independent of placement. Foreground process/session replacement changes epoch and retires execution-scoped credentials/claims. Runtime registration checks current terminal/process-birth/lifecycle facts outside render; OS verification belongs in platform traits, never core target-specific code. Missing evidence rejects/holds rather than guesses. After server restart, leases are invalid until exact revalidation; a reported session path alone is insufficient. Actor ID may remain only when that exact execution is revalidated; otherwise new binding requires consent and work reassignment is explicit. Durable original receipts keep their actor IDs.

### Durable outbox recovery authority

Journal append may include a bounded `deferred_deliveries` manifest: delivery ID, exact recipient actor and JSON pointer to an immutable opaque payload in that same append. Core resolves the pointer and stamps digest, original actor/principal/op/invocation and send capability at the **same durable CAS**. This is neutral delivery-intent evidence, not task interpretation. Pointer/payload must exist and be bounded; send grant is checked at commit.

After actor/provider crash, the currently admitted owner service obtains a separate `mailbox.intent.recover.v1` recovery-send lease referencing that committed cursor/manifest item. It cannot substitute sender, payload, recipient or delivery ID; original semantic author comes only from the host stamp, while recovery transport principal is the service. Verify prior delivery receipt first; already enqueued returns original receipt. Revoked recovery/send/namespace authority denies new enqueue, preserving pending intent; retired recipient requires explicit semantic readdress (new recorded intent), not transfer. This route is independent of the dead original invocation. Every unresolved deferred intent also holds a **mechanical transport pin** independent of semantic pins: namespace archive/unpin cannot prune its payload until authoritative durable enqueue or explicit verified abandonment. Stamped envelopes are immutable; `mailbox.edit` cannot bypass canonical work history even while waiting.

Ordinary executable service admission in 2B must register public action/decision handlers and string-named host capabilities, issuing an ordinary invocation lease (not pinned-package conformance authority). A separate public service-recovery invocation authenticates current service identity/generation and accepts only stored intent references. Process host calls still occur inside host-initiated invocation, including recovery; raw socket access is not a caller lease. This is required new production plumbing, not claimed current availability.

### Claim/run correlation and owner verification

The actor binds a current exact claim through `mailbox.run.bind.v1` before attempting a model start; host allocates durable run ID and freezes delivery/version/claim/actor/execution evidence. There is at most one logical run per exact delivery/version; different operation/claim cannot create another after start uncertainty. A new attempt requires explicit human recovery with a new source/delivery, never reuse of a route grant. The adapter persists that run and source through its actor checkpoint before native Pi submission. Start ACK is explicitly adapter-reported; loss requires receipt + persisted Pi-session reconciliation, not a second model request. Run evidence survives claim-lease expiry but cannot authorize a new start or replacement execution. Work owner reads only its stamped-intent run/claim receipt under a narrow public capability, verifying reply source/claim/run without borrowing the recipient credential. No source body is exposed outside ordinary granted reads.

## Storage and retention choice (V1)

Use a **new generic namespace journal/checkpoint primitive**, not an unqualified reuse of 128KiB namespace state/64receipt dedupe. The work extension materializes its task/thread graph from journal records and checkpoints; core stores opaque JSON plus mechanical actor/op/cursor metadata. No host work database, task enums or cross-store transaction. Existing store contracts stay unchanged.

V1 advertised defaults: 64MiB charged bytes per namespace journal, 100,000 journal records, 256MiB total session grant; lower operator quotas may be configured and advertised. Each append payload max64KiB UTF-8 encoded JSON; logical checkpoint max1MiB (up to32 immutable journal chunks <=32KiB each, committed by cursor list + concatenated content digest; no inline1MiB service frame); page max128records/512KiB, provider invocation/input/result max64KiB, display labels max240bytes. Effective page byte ceiling is the minimum of advertised method limit, configured grant and transport frame budget (existing executable service IPC max256KiB minus framing). Journal read returns checkpoint metadata/chunk cursors, not an oversized inline checkpoint; requested record IDs fetch its chunks. Charged bytes include payload, receipts, tombstones, index and checkpoint (no unbounded side indexes). Limits fail before effect when known; inability to establish durable boundary yields uncertain/repair fence. New quota does not delete old state.

Mailbox: max256 waiting/claimed envelopes per actor and64MiB charged store per namespace (within session budget); envelope max64KiB including body/attribution. Body max32KiB in the work schema. No implicit expiry/deletion of waiting, claimed, uncertain, outbox-pending or unaccepted report data. Payload/content validation is extension-owned; rendering escapes terminal control sequences and never auto-fetches evidence URLs/files.

### Canonical inputs and immutable admission

Digest algorithm is `vqro-json-int-v1`: Unicode scalar strings only; object keys sorted by UTF-8 byte lexicographic order; UTF-8 JSON string escapes for quote/backslash/C0 with short escapes for backspace/formfeed/newline/carriage-return/tab, lower-case `\\u00xx` otherwise; slash and non-ASCII scalars unescaped; arrays preserve order; no insignificant spaces. Numbers are integers within +/-9007199254740991, decimal canonical representation; negative zero/fraction/nonfinite/unsafe numeric counters rejected (counters are decimal strings). Strict wire decode rejects duplicate object keys after unescaping, including nested duplicates. Domain-separated SHA-256 of canonical bytes is host/work-computed, never a supplied digest treated as authority. Action semantic digest domain is `vqro.action.input.v1` plus NUL over canonical `{namespace, service_id, action, input}`; caller actor/operation key is separately host-attributed. Expected provider generation, receipt domain, invocation deadline and connection data are fences, not semantic payload fields. Reusing operation key after provider update still requires original lookup, never fresh blind invocation. Opaque journal record digest domain is `vqro.journal.record.v1` plus NUL over canonical opaque payload + resolved deferred manifest; host computes digests/stamps. Exact field selection/domain per contract is versioned; decision input domain is `vqro.decision.input.v1` plus NUL, selecting contract/point/scope/input+policy revisions/mode/budget/context/input (not request ID or digest itself).

Admission clones/freezes the validated request. Result fences compare actual current canonical digest as well as revisions; same-revision body/context mutation cannot pass. Key ordering and integer lexical forms cannot create two semantic operations. `canonical.mjs` and Python stdlib fixtures demonstrate cross-language form/duplicate rejection, not qualification of a production wire parser.

Retain operation IDs + stable semantic digests + terminal outcome/commit cursors and transport version/provenance tombstones for the **entire store generation**. Compaction may remove accepted/explicitly archived payloads only after extension-authorized archive, retaining dedupe/history metadata and pinned pending records. Never evict receipts at a numeric horizon and then report absent. At quota: block new mutation with actionable quota state, permit reads/recovery. Operator archive/export/reset is explicit and hard-to-reverse: append defaults pinned; the work owner unpins only after semantic archive approval, core never infers accepted tasks. Reset requires a sealed exact-head export manifest, explicit operator acknowledgement that the export was durably saved/hash-checked, and disposition of every pinned record (including explicit abandonment if reset is deliberately destructive). The client writer fsyncs/hash-checks the backup before acknowledgement; host records that assertion and does not pretend it independently verified another machine's disk. Any head change invalidates it. No V1 automatic recovery reset is permitted. Reset creates a new store ID/generation and invalidates old write leases. Old-generation lookup returns retired, not absent; old requests cannot replay into the new store. No automatic reset/cleanup in V1.

Checkpoint chunk format in an ordinary opaque journal record is `{ "checkpoint_chunk": { "index": 0, "bytes_base64": "..." } }`, with no other chunk fields; index0..31, canonical RFC4648 padded base64, decoded<=32768bytes. Checkpoint commit orders cursors by supplied index, rejects missing/duplicate/out-of-order/non-owner/non-current-store chunks, total<=1MiB, and verifies SHA-256 of concatenated decoded UTF-8 canonical snapshot bytes. Chunks/default pins remain until a verified replacement checkpoint/archive; partial chunk writes are harmless retained records, not a valid checkpoint. Work parses its own reconstructed snapshot; core knows bytes/cursors/hash only.

Journal append transaction atomically enforces expected store/head, namespace authority and idempotency, stores opaque records + host attribution and receipt, then returns only after durable persistence. Torn/uncertain replacement enters repair-required; restart validates/reconstructs before writes. Cancellation/disconnect after persistence begins cannot claim not-committed. Checkpoint references an exact committed head/hash; bad/partial checkpoint falls back to retained log or repair, never silently invents state. Core does not decide which work is accepted; extension pins/archives records through public authority.

## Capability/failure matrix

| Case | Required public outcome / no forbidden effect |
| --- | --- |
| Missing new method/capability | work/composer action unavailable; keep draft, terminal/other endpoints stay usable |
| Unknown namespace/action/contract version | reject before invocation; no first-party fallback |
| Forged actor/context/role label | reject/context ignored as untrusted input; no privilege gain |
| Wrong namespace/service generation or revoked grant | deny before new effect; late result fenced; lookup earlier durable receipt |
| Replaced execution/pane move | new execution denied old claim; pane move alone updates placement, does not address by label |
| Server restart/unknown identity | hold claims/writes until revalidation; no auto retarget/wake |
| Reused operation ID with different semantic payload | conflict; original receipt/history unchanged |
| Duplicate committed operation after retry/update | original receipt; no second entry/delivery/effect |
| Conflict task/thread revision | extension conflict; resnapshot, keep draft; no silent overwrite |
| Journal CAS conflict | no append; provider resnapshot/revalidate, not stale decision auto-apply |
| Caller/provider cancelled before persistence | canceled only if absence is certain; otherwise unknown + lookup |
| Disconnect after persist but before ACK | lookup original key; committed data remains authoritative |
| Provider crashes after append/before callback | broker resolves verified journal receipt; never trusts callback absence as noncommit |
| Outbox committed/enqueue failed | pending durable intent, visible recovery; stable delivery lookup before send retry |
| Enqueue succeeded/journal-link ACK lost | dedupe receipt reconciles; no second delivery |
| Claim/edit race | one CAS wins; loser gets conflict; consumed content/version immutable |
| Claim lease expires | same-execution explicit renewal/recovery; no different-execution automatic claim/replay |
| Adapter run started/claim ACK lost | source version/run correlation persists; reconcile consumed observation, do not restart run blindly |
| Reply lost/submit uncertain | preserve final text + operation ID; receipt lookup, no duplicate post |
| Explicit reply tool + final observer | same run/source dedupe or explicit suppression; one reply |
| Abort/error/queued continuation | no false final reply/completion; notification-only agent_settled plus exactly matched persisted response/outcome proof required |
| Report arrives | evidence/report state only; never acceptance |
| Accept races newer report/change | exact report/task revision CAS; stale result cannot accept new work |
| Provider timeout/failure/bad proposal | recorded deterministic fallback/no-op; no model in delivery path |
| Human override races provider | current revision wins via CAS; old provider cannot undo override |
| Quota/storage failure | no optimistic ACK; preserve pending/receipt state; reads/recovery permitted if verified |
| Dedupe/retention horizon | no implicit horizon inside generation; quota then explicit archive/reset, never absent+replay |
| Malicious body/evidence | bounded text, no terminal execution/auto file/network fetch |
| Idle with active work vs unknown/blocked | extension advisory only, reason/observation revision; no automatic resume |

## Owner qualification gate

2B must demonstrate actor ticket replay/wrong subject/replacement/restart, namespace/grant/provider fencing, journal fsync/CAS/dedupe/repair, mailbox claim/edit/lease/outbox reconciliation and quota/reset behavior with private roots and no work-block model. Protect published wire/method fixtures unmodified. 3 owners then prove shared actions/actor policy/decision results, adapter settled ordering and modal draft/input behavior. Core render accesses only cached scalar/projections; no actor process-tree/storage/decision work inside render. Profile1/15 populated panes whenever layout/render widens.
