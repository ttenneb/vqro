# `vqro.service.v1`

Status: production runtime instantiation with staged host-call and contribution authority. Process protocol 2 and WebAssembly Component Model services implement the same dispatcher contract. Enabled installed components can be verified, instantiated, negotiated, supervised, and restored, but they receive no production host-call lease, provider admission, visible publication, or feature authority. See the [extension platform status](extension-platform-status.md).

Every runtime is bound to an exact package, namespace, service ID, and nonzero generation. The dispatcher validates this identity on startup and invocation, enforces deadlines and cancellation, checks bounded canonical frames, records auditable request metadata, and rejects stale generations before transport I/O.

The runtime interface has backend-neutral start, invoke, event-delivery, and stop semantics. Lifecycle states and restart policy are shared above both backends. Existing manifest-v1 and bundled process services enter through a named legacy compatibility factory and retain process protocol 2 behavior. Manifest-v2 runtime selection is driven only by the verified service declaration.

The generated [`vqro-service-v1.schema.json`](vqro-service-v1.schema.json) defines request, event, host-call, host-response, identity, and normalized error envelopes. Host calls carry generation, call ID, depth, capability, method, namespace, and parameters. The shared runtime router—not either transport—requires exact depth one, permits one concurrently outstanding host call and eight total attempted host calls per invocation, and validates the frame, identity, namespace, method, and capability before dispatch. Queues and frames remain bounded.

The additive [`host.state.v1`](host-state-v1.md) snapshot/transaction adapter and read-only [`host.terminals.v1`](host-terminals-v1.md) snapshot adapter are staged for installed package-v1 conformance only. A host-selected read purpose may atomically issue one package/service/artifact/scope context containing `state.snapshot`, `terminals.snapshot`, or both, intersected with the verified installed-package grants. The composite context never grants `state.transact`; existing write conformance uses a separate staged path. Normal production package-service invocations do not issue either kind of lease. Legacy services, preflight, and ordinary package calls retain the disabled router. Terminal mutation, relationship, evidence, managed-file, document, and UI authority remains unavailable.

Installed process packages execute only a verified package-relative payload selected by the manifest for the current target. The host revalidates the immutable archive on every start, copies the checksum-bound payload into unpredictable private staging, and uses that canonical absolute copy with fixed argv, no shell command or PATH lookup, an immutable package working directory, and a cleared environment containing only explicit non-secret Vqro metadata. Native processes remain trusted same-user code rather than sandboxes. Unix process groups contain descendants that remain in the group; Windows kill-on-close Job Objects contain the process tree. Both are retired on cancellation, deadlines, detected crashes, and drop.

The checked-in WIT world is `vqro:extension/service@1.0.0` under `wit/vqro-extension-service/world.wit`. Its byte payloads are canonical JSON instances of this contract. A component gets one store and instance per worker, at most 64 MiB linear memory, one memory, four tables with 4,096 elements each, 16 lowered core instances and an approximately 1 MiB Wasm stack. The service world defines no resource handles. Fuel is an internal runaway bound; epoch interruption enforces wall-clock deadlines and cancellation. Traps, resource exhaustion, fuel exhaustion, deadlines, and cancellation are normalized and retire the generation.

Component packages are compiled only from checksum-verified package bytes. A factory retains code compiled from those verified bytes and admits only one active generation, so later archive mutation cannot alter that factory's execution; constructing a new factory revalidates the archive. The component backend links only the checked-in Vqro service world: no WASI filesystem, CLI, environment, argument, clock, random, polling, network, socket, or name-lookup interface is linked. Components requiring any undeclared import fail preflight. Host calls and logs use bounded WIT imports, and logs are limited to 64 KiB per invocation. No host API socket or Vqro session credentials are exposed.

Process protocol limits remain 256 KiB frames, a three-second handshake, a 750 ms default request deadline, sequential requests, bounded writer/frame queues, bounded stderr lines/rate, and the existing three-restart backoff policy. No runtime request occurs from rendering or per-frame client work.
