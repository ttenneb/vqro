title: Extension platform status
description: Distinguish legacy executable plugins from sandboxed component packages and their current capabilities.
---

Vqro currently has two extension models with different trust and capability boundaries.

| Capability | Legacy executable plugin | Component extension package |
| --- | --- | --- |
| Manifest | v1 | v2 or v3 in deterministic `.vqrox`; v2 is frozen and v3 adds exact service contracts |
| Runtime | Trusted same-user process | WebAssembly Component Model component executed by Wasmtime with only the Vqro WIT world linked |
| Repository build commands | Legacy Git install may run confirmed commands | Never run by package installation |
| Git-installed native process | Supported by the legacy plugin path | Rejected |
| Runtime start and supervision | Available | Available |
| Production host document | `host.document.v1` for admitted protocol-2 services | Exact pinned Collections and Spaces packages publish audited cached documents |
| Production state/terminal host calls | Not supplied by the package dispatcher | Revocable reads for exact pinned Collections audit/action planning; ordinary packages receive none |
| Client-visible component contribution | Not applicable | Collections publishes synchronized compatibility projections; Spaces publishes an audited navigation document |
| Collections policy authority | Unavailable; compiled provider removed | Exact pinned package after atomic snapshot-v7 cutover; fail-closed when absent, unavailable, or replaced |
| Spaces projection authority | Unavailable; compiled and bundled providers removed | Exact pinned zero-host-call package; fail-closed when absent, unavailable, stale, or replaced |
| Package-to-package services | Unavailable | Experimental exact-artifact bindings and one bounded, non-recursive component read call; the `extension.doctor` host/CLI seam exists, but independently published Doctor/Health artifacts and production pins remain unavailable |

A component package that installs and starts successfully has crossed only the verified artifact and runtime boundaries. Ordinary packages still cannot read host state. A manifest-v3 package may declare exact descriptor-digested imports and exports, but declarations and discovery grant no authority. A user-approved binding names exact consumer and provider artifacts, methods, information-flow categories, and byte limits. The experimental R1 relay permits one read call, gives the provider no host-call router, and never waits on the App actor.

The exact pinned Collections package additionally receives bounded read leases. Once all scopes pass audit, Vqro atomically checkpoints package state and snapshot-v7 authority, then uses package profiles and typed action plans. The exact pinned Spaces package instead receives one complete host-authored snapshot as invocation parameters and has zero host-call capabilities. Neither feature has a bundled fallback; failure removes only package-owned authority while generic workspace, pane, and PTY access remains available.

The Extensions inventory reports provenance explicitly: independently installed component archives are **sandboxed packages**, distribution-owned entries are **bundled providers**, and detected coding tools are **agent integrations**. Curated discovery does not change kind or grant authority.

## Security distinction

Legacy executable plugins run with the operating-system access of the Vqro user. Process supervision and descendant containment stop managed processes, but do not sandbox their filesystem or network access.

Git-installed component packages use exact commits and deterministic archives. Vqro executes no repository build command, rejects native process services, and links no ambient WASI filesystem, network, process, environment, clock, or socket interfaces. Curated status does not add capabilities.

See [Plugins](/docs/plugins/) for legacy authoring and security guidance. See [Marketplace](/docs/marketplace/) for the component package installation journey.
