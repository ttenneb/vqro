---
title: 拡張プラットフォームの状態
description: 従来の実行可能プラグインとサンドボックス化されたコンポーネントパッケージ、および現在の能力を区別します。
---

Vqro には現在、信頼境界と能力が異なる 2 つの拡張モデルがあります。

| 能力 | 従来の実行可能プラグイン | コンポーネント拡張パッケージ |
| --- | --- | --- |
| マニフェスト | v1 | 決定論的 `.vqrox` 内の v2 |
| ランタイム | 同一ユーザーとして信頼して実行するプロセス | Vqro WIT world だけをリンクし、Wasmtime で実行する WebAssembly Component Model コンポーネント |
| リポジトリのビルドコマンド | 従来の Git インストールでは確認後に実行可能 | パッケージインストールでは実行しない |
| Git インストールされたネイティブプロセス | 従来のプラグイン経路で対応 | 拒否 |
| ランタイム起動と監督 | 利用可能 | 利用可能 |
| 本番ホストドキュメント | 登録済み protocol-2 サービス向け `host.document.v1` | 未提供 |
| 本番の状態/ターミナルホスト呼び出し | パッケージディスパッチャーからは付与しない | 適合試験のみ。通常のパッケージ呼び出しにはリースなし |
| クライアントに表示されるコンポーネント寄与 | 対象外 | 未提供 |
| Collections ポリシー権限 | 組み込みホスト互換プロバイダー | 外部パッケージは適合試験のみ |

コンポーネントパッケージのインストールと起動が成功したことは、検証済み成果物とランタイムの境界を通過したことを示します。ホスト状態の読み取り、プロバイダースロットの所有、クライアントへの公開、または機能権限の取得を意味しません。

## セキュリティ上の違い

従来の実行可能プラグインは Vqro ユーザーと同じ OS 権限で動作します。プロセス監督と子孫プロセスの封じ込めは管理対象プロセスを停止するための仕組みであり、ファイルシステムやネットワークアクセスをサンドボックス化しません。

Git からインストールするコンポーネントパッケージは、正確なコミットと決定論的アーカイブを使います。Vqro はリポジトリのビルドコマンドを実行せず、ネイティブプロセスサービスを拒否し、環境由来の WASI ファイルシステム、ネットワーク、プロセス、環境、時計、ソケットの各インターフェースをリンクしません。キュレーション済みであることは能力を追加しません。

従来の作成方法とセキュリティ指針は[プラグイン](/ja/docs/plugins/)を、コンポーネントパッケージのインストール手順は[マーケットプレイス](/ja/docs/marketplace/)を参照してください。
