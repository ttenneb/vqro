このページでは、ホスト protocol `2` が実装する従来の manifest-v1 プロセスサービス契約 `vqro.extension-service.v1` を説明します。生成スキーマは `docs/next/api/vqro-extension-service.schema.json` です。

Manifest-v2 コンポーネントパッケージは、別のランタイム中立契約 `vqro.service.v1` とチェックイン済み WIT world を使います。検証済みランタイムは本番でインスタンス化できますが、ホスト呼び出しリース、document-v2 プロバイダー登録、表示公開、機能権限はまだ段階的導入中です。[拡張プラットフォームの状態](/ja/docs/extension-platform-status/)を参照してください。

## トランスポートとライフサイクル

サービスは同一ユーザーとして動作する信頼済みプロセスであり、OS セキュリティサンドボックスではありません。Vqro は監督下で起動し、サイズ制限付きの改行区切り JSON フレームを送受信し、stderr を排出し、ハンドシェイクと要求のタイムアウトを適用し、無効化、置換、終了時にプロセスツリーを停止します。

サービスは最初に protocol `2`、正確なサービス ID、要求能力、対応する固定メソッドを含む `hello` を書きます。ホストは不一致を拒否し、許可能力と対応メソッドを `welcome` で返します。要求はホスト発行 ID を持ち、応答は同じ ID と `result` または `error` のどちらか一方を含めます。

## 対応メソッド

安定した従来プロセスサービス面には `view.render`、`view.action`、`host.document.render`、`host.document.action` があります。サードパーティのホストドキュメントが現在利用できるのは `terminal_groups` だけです。これらの名前は、段階的導入中の document-v2 やコンポーネントパッケージの寄与経路を有効にしません。

動的アクション選択肢、ターミナルリソース、確認契約は、別仕様で安定と宣言されるまでは基盤または実験的な面です。

## 検証

`vqro plugin validate PATH` はコードを実行せずにパッケージを解析し意味検証します。`vqro plugin conformance PATH` は宣言されたサービスを本番スーパーバイザーとハンドシェイクで明示的に実行します。成功は 0、検証失敗は 1、使用法エラーは 2 を返し、`--json` は機械可読出力を生成します。

互換性のない変更には、新しい名前付き契約またはプロトコル番号が必要です。既存 protocol-2 フレームの意味は再解釈しません。
