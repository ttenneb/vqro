Herdr プラグインマーケットプレイスは、コミュニティ製プラグインを探せるインデックスです。
[herdr.dev/plugins](/plugins/) で閲覧できます。これは公開 GitHub リポジトリの
自動インデックスであり、審査済みカタログではありません。

## Vqro Extensions

Vqro には、ホストが管理するネイティブの Extensions マーケットプレイスもあります。
メインメニューから **Extensions** を開くと、チェックイン済みのキュレーションされた
インデックスを検索し、カテゴリで絞り込めます。インストール、削除、更新、ロールバック、
データの完全削除はそれぞれ確認が必要です。ピン留めされたエントリは正確な Git コミットを取得し、ソースと
マニフェストのダイジェストを検証してから管理領域に保持します。ソースから導入するエージェント統合では、更新前の検証済み成果物を
ロールバック用に残し、可変参照を再取得しません。Delegation と Agent Status はホストに組み込まれた互換プロバイダーです。Collections と Spaces は、正確な Git コミットから導入する独立ビルドのコンポーネントパッケージであり、Browse のカタログ行ではなく Installed に **sandboxed package** として表示されます。削除しても設定と状態は保持され、
**delete data** を別途実行した場合だけ消去されます。組み込みエントリは同じ Extensions 画面に表示され削除できますが、その互換レコードは package-v1 ランタイムレコードではありません。

ダウンロードされた実行可能パッケージは、すべてのサービスが `vqro:extension/service@1.0.0`
コンポーネント world を使う場合にだけ受け入れられます。Wasmtime 上の WebAssembly Component Model コンポーネントとして、Vqro WIT world だけをリンクし、明示的なホスト能力とリソース制限の下で実行されます。キュレーション済みであることは能力や権限を追加しません。インストールではサービスを検証、インスタンス化、ネゴシエート、監督、再起動後に復元できます。通常のパッケージにはホスト状態/ターミナルリースも機能権限もありません。正確な Collections パッケージだけが制限付き読み取りリースを受け、正確な Spaces パッケージはホスト呼び出し能力を持たず、完全なホスト作成パラメーターだけを受け取ります。どちらの出力も公開前に意味検証されます。従来の明示設定されたプロセスプラグインは別の互換機能であり、Extension パッケージとしてインストールできません。エージェントパッケージの状態とアダプターの導入状態は別々に表示されます。

### 正確な Git リビジョンからインストール

**Extensions** で **g** を押し、認証情報を含まない HTTPS Git URL、完全な 40 文字コミット、必要ならリポジトリ相対の `.vqrox` パスを入力します。Vqro はそのコミットだけを取得し、サブモジュールとリンクされたパッケージパスを拒否し、決定論的パッケージを検証します。ネイティブプロセスランタイムを要求するサービスが 1 つでもあれば、パッケージ全体を拒否します。

確認画面は URL、コミット、パッケージとマニフェストのダイジェスト、名前空間、コンポーネントサービス、要求能力を表示します。承認はそれらのダイジェストに結び付けられます。更新とロールバックにも正確な成果物の確認が必要で、これらの操作はペインの PTY を置換または再起動しません。

## プラグインを探す

[マーケットプレイス](/plugins/)には、GitHub トピック `herdr-plugin` が付いており、
デフォルトブランチに必須メタデータを解析できる `herdr-plugin.toml` が 1 つ以上ある
公開リポジトリが掲載されます。リポジトリとプラグインのメタデータを検索でき、
リポジトリカードを人気順、最近の活動順、新着順で並べ替えられます。各カードは
ソースリポジトリにリンクし、その中で検出されたすべてのプラグインを表示します。

掲載は自動かつ無審査です。掲載されているのはリポジトリが自らトピックを
付けたからであって、Herdr が検証したからではありません。インストールする前に
[信頼に関するガイダンス](/ja/docs/plugins/#信頼とセキュリティ)を確認してください。

## プラグインをインストールする

マーケットプレイスはインストールの上に発見の仕組みを足すものであり、
インストールを置き換えるものではありません。どのプラグインも GitHub から
直接インストールできます:

```bash
herdr plugin install owner/repo[/subdir...]
```

ルートまたはサブディレクトリに `herdr-plugin.toml` マニフェストを置いた
通常の公開 GitHub リポジトリを公開すれば、このコマンドが機能します。
マニフェストと作成方法のリファレンスは[プラグイン](/ja/docs/plugins/)を
参照してください。

## 自分のプラグインを掲載する

公開リポジトリに GitHub トピック `herdr-plugin` を追加し、デフォルトブランチに
必須メタデータを解析できる `herdr-plugin.toml` を 1 つ以上置いてください。
マニフェストはルートにもサブディレクトリにも配置できます。マーケットプレイスは
1 リポジトリにつき 1 枚のカードを使い、有効な各マニフェストを個別にインストール
できるプラグインとして表示します。インデックスは 30 分ごとに自動更新されます。

## 掲載に表示される内容

各カードには GitHub リポジトリの名前、オーナー、説明、スター数、主要言語、
最終 push 時刻が表示されます。プラグイン行には各マニフェストの `name` と `version`
が表示され、正確なソースディレクトリにリンクします。インデックスにはパス、`id`、
`name`、`version`、`platforms`、`min_herdr_version` と、デフォルトブランチの正確な
コミットが記録されます。フォーク、アーカイブ済みリポジトリ、有効なプラグイン
マニフェストがないリポジトリ、不正なメタデータは一覧から除外されます。
