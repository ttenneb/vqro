description: 区分旧版可执行插件与沙箱化组件软件包及其当前能力。

Vqro 当前有两种具有不同信任与能力边界的扩展模型。

| 能力 | 旧版可执行插件 | 组件扩展软件包 |
| --- | --- | --- |
| 清单 | v1 | 确定性 `.vqrox` 中的 v2 |
| 运行时 | 以同一用户身份运行的受信任进程 | 由 Wasmtime 执行且仅链接 Vqro WIT world 的 WebAssembly Component Model 组件 |
| 仓库构建命令 | 旧版 Git 安装可在确认后执行 | 软件包安装从不执行 |
| Git 安装的原生进程 | 旧版插件路径支持 | 拒绝 |
| 运行时启动和监督 | 可用 | 可用 |
| 生产宿主文档 | 已接纳 protocol-2 服务的 `host.document.v1` | 切换后由精确固定的 Collections 软件包发布经审计的缓存兼容文档 |
| 生产状态/终端宿主调用 | 软件包分派器不提供 | 仅为 Collections 审计和操作规划授予可撤销读取;普通软件包不获得租约 |
| 客户端可见的组件贡献 | 不适用 | Collections 配置同步发布 generation-1 文档与结构投影 |
| Collections 策略权威 | 不可用;内置提供程序已删除 | snapshot-v7 原子切换后由精确固定的软件包持有;未安装、不可用或被替换时关闭失败 |

组件软件包安装并启动成功,仅表示它已通过已验证产物和运行时边界。普通软件包仍不能读取宿主状态。精确固定的 Collections 软件包额外获得有界读取租约;所有作用域通过审计后,Vqro 原子检查点软件包状态与 snapshot-v7 权威,随后使用软件包配置和类型化操作计划。系统不再包含内置 Collections 提供程序或降级后备。宿主继续持有 PTY、验证计划并执行效果。精确软件包未安装或不可用时,所有 `collection.*` 方法会被禁用,但通用终端访问保持可用。

## 安全边界区别

旧版可执行插件以 Vqro 用户的操作系统权限运行。进程监督与后代进程约束可以停止受管进程,但不会对其文件系统或网络访问进行沙箱隔离。

从 Git 安装的组件软件包使用精确提交和确定性归档。Vqro 不执行仓库构建命令,拒绝原生进程服务,也不链接环境赋予的 WASI 文件系统、网络、进程、环境变量、时钟或套接字接口。精选状态不会增加能力。

旧版编写方式和安全指南见[插件](/zh-cn/docs/plugins/);组件软件包安装流程见[插件市场](/zh-cn/docs/marketplace/)。
