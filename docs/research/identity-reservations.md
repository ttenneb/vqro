# Cached resource identity reservations (C4)

AS4 chose keep mail + identity for disappeared agents. Core supplies only the generic identity mechanism: cached facts can disappear without discarding a bounded reservation of the complete `(provider,instance,backend_ref,incarnation)`→rN. Coordination extensions own tombstones, membership, held/unknown mail and restart-paused behavior; no native work or replay is supplied here.

## Storage and lifetime

`IdentityMap::forget_cached` uses the existing identity candidate and atomic durable writer. It removes unavailable active facts and reserves the exact identity; a return consumes that reservation only when the candidate is actually adopted. Native forget, authoritative removal and replacement retirements never create reservations; they invalidate matching OLD hints in the SAME candidate/write, including when no active facts remain. Reserved identities participate in provider-instance/authoritative fast-path decisions. Different full identities get new monotonic IDs, never a reserved ID belonging to somebody else.

The set is bounded to4096 entries of≤2KiB encoded each (≤8MiB logical record bytes, not RSS or total file size). It evicts oldest-forgotten first; full identity allocations are shared by its lookup/order indexes. Oversized hints are not cached but never refuse registration/cached-forget. Counter wrap renumbers order without evicting. Snapshot metadata exposes count/encoded bytes/limits, actual file-backed persistence, confirmation and recovery notice, not message/effect authority.

The coordinator explicitly required persistence rather than the initially proposed volatile cache: routine core restarts must preserve the human's keep-identity choice. Ordered reservations are therefore part of the SAME `resources.json` candidate as active mappings and rN high-water, never a second side file or journal. Restart restores the bounded order and accounts reserved IDs in high-water. Old files default to an empty reservation list. Malformed, duplicate, oversized or active-colliding OPTIONAL cache rows are discarded with a persistent recovery notice; all readable numeric rN values/high-water are retained before fresh allocation. Healthy active mappings and safe-mode boot remain available. Original source is unchanged at startup; the next admitted identity replacement confirms the recovered state/notice. Whole identity-file syntax/I/O failure stays strict, per coordinator ruling; no unseen high-water is guessed. Retired legacy two-field identities still cannot prove a full tuple and are not imported into reservations.

A clean write failure adopts neither active retirement/reappearance nor cache changes. An uncertain post-rename write adopts BOTH, reports durability_unconfirmed and must later confirm via the existing identity writer; it is not permission to replay an effect. Cached facts/provider metadata still reap; an identity hint does not count as an active provider/resource or keep a process alive. No pause/configuration/grants/mail fields are fabricated or modified.
