# Platform small fixes: A2/A3/A4/A7 (2026-11-17)

- A2: Pi uses a host-resolved neutral python3 bridge launcher, never sys.executable or an interpreter chosen from the core OS. Per-runtime bridge_argv/bridge_env configure the terminal host (Windows example: py,-3,-m,pi_bridge). Custom launchers do not inherit the core's module path. Local default package lookup is retained. This does not implement remote reachability.
- A3: herdr provider instance remains native permanent core.id; default name is herdr@core-id. Display core.name stays software metadata only. Tmux instance remains native pid/start-time/server nonce; default name uses the server nonce. No hostname or /proc fallback chooses names, so identical display hostnames do not collide. Explicit --name remains a registry identifier, not a display rename API.
- A4: local refs remain tN. Remote refs are opaque JSON tuples of version, Machine.id, optional session and terminal id. Alias/address remains display metadata. Unknown/multihop identities are withheld rather than guessed. Alias-only events cannot rebind old machine facts: a bounded read-only inventory refresh obtains Machine.id from the same native snapshot, retaining newer local observations. Refresh timeout disconnects rather than inventing facts.
- Per parent decision, remote kill/attach and other remote effects are unsupported until hc offers identity-safe addressing. This is declared in remote.machines and rejected before dispatch. No alias lookup race, hidden attach or terminal.send/keys emulation is introduced. Upstream ask: accept permanent machine id + session + terminal id atomically for effects; retain aliases for display only.
- A7 moved from main into prim-herdr after backends-as-extensions. PRIM_HERDR is JSON argv (or one literal executable), --hc/--hc-arg are literal, default paths are vectors, and PATH uses std::env::split_paths. Paths/arguments containing spaces survive. Legacy whitespace command values need JSON conversion; no shell is invoked by parsing.

Migration: existing local refs/instances are unchanged with the same explicit provider name. New default registry names create a new namespace; old ids are never adopted into another backend. Pin the prior --name if local namespace continuity is needed during cutover. Runtime resume credentials bound to an old host id may require explicit restart if that namespace changes; nothing resends input. Remote legacy alias refs are replaced through normal complete-inventory retirement/tombstones, not aliased to new tuples. A core conformance regression verifies old alias ids and replaced machine ids are durably retired.

Evidence: A2 tests failed on sys.executable/core module-path injection before the fix. Provider name and spaced argv tests failed on hostname/split_whitespace. Remote tests failed on alias rename/reuse and unknown machine identity before the fix; all now pass. Additional coverage checks ignored alias-only updates, session distinction, local compatibility, durable tombstones and spaced PATH/install paths.

Final scoped quick gate: PASS4/4, zero warnings,109 Python tests; all ordinary Rust tests pass. Relevant real-private herdr provider4/4 and tmux provider6/6 opt-ins pass.
